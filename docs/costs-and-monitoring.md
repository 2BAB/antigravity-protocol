# 成本与安全审查

## 背景

`agy` 在跑一个工具之前会做一次检查。这套检查是编译进二进制的，没有开关，也没有配置文件可改。

有意思的是检查本身很便宜——几十微秒。贵的是它判定「可疑」之后触发的那次小模型复审，一次一到一秒半，而且每次都算在你的额度上。

## 三类结果

第一类，命令在白名单里，判定放行。`git`、`npm`、`head`、`tail` 这类常见命令属于这一类。不会有复审。

第二类，命令不认识。比如你自己写的脚本、内部 CLI，判定可疑，触发复审。日志里写的是 `reason="unknown_command"`。

第三类，工具本身不在检查器的认知范围。比如通过 MCP 调的某个工具，判定是 `unsupported_tool`，同样触发复审。

复审的结果基本都是通过，但它已经花掉了那一秒多。

## 几个实测结论

复审的耗时在一秒到一秒半之间，跟任务复杂度无关。

想通过权限配置把它关掉是不行的。我试过往权限允许列表里加 `command(<命令名>)`，复审照常触发，reason 还是 `unknown_command`。那套权限配置管的是「要不要问你」，不是「要不要复审」。

`--dangerously-skip-permissions` 也不影响它。这个 flag 关的是交互式确认，不是审查。

## 上下文与单跳成本

同一个模型、同一句话「讲个笑话」，实测数据：

- 全新会话、约一万四千 token 输入：约 7 到 8 秒
- 同会话继续、两千多新 token 加一万二缓存：5 秒到 22 秒
- 上下文到两万以上：更慢

同一件事的耗时能差四倍，主要来自后端排队，不是我们的代码。

## 模型档位不一定更快

拿同一句简单任务对比，flash 档和 argon 档的单跳耗时经常互有胜负，方差大于差距。指望换个档位救延迟，大概率失望。

我的结论是：单跳五到十秒是这条链路的地板，长尾二十秒以上。要做延迟预算，按这个来。

## 带走这两条

1. 每次不认识的命令或工具调用，固定多花一秒多。能把调用次数合并就合并。
2. 不要试图关掉审查。它是内建的，把精力放在减少调用次数上。
